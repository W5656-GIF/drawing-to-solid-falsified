# 2D 图纸 → 3D 模型：一次证伪

**大模型在图模转换中的幻觉约束**
——信息获取阶段与校核检验阶段的工程总结

> 我们搭了一套完整的流水线，让大模型把机械图纸读成约束、算成计划、建成 SolidWorks 三维实体，并要求模型的三项物理属性（体积 / 质心 / 包围盒）与**独立算出**的理论值闭合到 `max(0.1 mm, 1%)` 以内。
>
> 它跑通了。11 个真实零件里 8 个三项闸门 3/3 通过。
>
> 然后我们算了账：**这门生意不成立**——因为零件是先有三维、后有二维的，反推是在往上游捞东西。
>
> 但两个阶段里真正值得公开的，不是建模方法，而是这两条：
>
> **信息获取阶段的全部工程，是"不给幻觉留填空的位置"；校核检验阶段的全部工程，是"不让幻觉验证幻觉"。** 后者比前者贵一个量级，也才是这套系统里唯一能独立搬走的东西。

---

## Abstract

We built an end-to-end pipeline in which a large language model reads mechanical drawings, converts them into an evidence-bound constraint set, plans the build, and drives SolidWorks — with acceptance gates on volume, centre of mass, and bounding box, all three closed to `max(0.1 mm, 1%)` against **independently computed** theory values. It works: 8 of 11 real mechanical parts pass all three gates.

**The engineering problem was never "can the model read the drawing". It was that a language model hallucinates in exactly the shape of a correct answer.** Not wild invention — invented *gaps*. A dimension chain that does not close gets a plausible number; a view whose section type is ambiguous gets a confident verdict; a tool that silently failed gets reported as passing. The output is correctly formatted, dimensionally reasonable, and lets every downstream calculation succeed.

This document summarises the two phases as two families of hallucination controls:

- **Information acquisition** — do not give the model anywhere to write a number it did not get from evidence.
- **Verification** — do not let the model use a value it derived as the expectation for the value it produced.

It is not commercially viable, and not because it does not work: 3D is designed first, 2D drawings are a downstream artefact, so the reverse direction has demand only where the 3D source is already lost. The verification phase is nonetheless the reusable part — it flows *with* the pipeline, and it audits models built by any process, human or automated.

## 0. 结论（先给结论）

### 0.1 关于生意

1. **2D→3D 是逆向工程，而现代设计是 3D→2D。** 三维模型是主产品，二维工程图是从它投影 + 标注出来的派生物。所以"把 2D 变回 3D"这条管道的方向是反的：**凡是还在设计、还在生产的零件，三维模型本来就有。** 你要做的事，别人在上游已经做完了。

2. **需求只存在于 3D 源头已经丢失的缝隙里**——老图数字化、供应商只给图不给模型、有图无模型的合规建档。这条缝隙的画像与我们能提供的东西恰好相反：一次性、低批量、图纸质量最差、预算最低，而且**没人能验收**。

3. **就算缝隙里有单，成本也做不成生意。** 盈亏平衡点是直通率 61.7%，实测 73% 和 29%，真实批次落在亏的一侧。

4. **校核检验阶段是顺着管道的。** 模型核对 / 图纸评审是正向流程里既有的、刚性的、高频的环节，而且它**不需要先重建 3D**——它能审人建的模型。

### 0.2 关于幻觉

大模型在图模转换里的幻觉，**不是凭空编造**——那种一眼就能看出来。真正危险的是另一种：

> **在缺口处填一个"如果图纸完整，本该就是这个值"的数字。**

它格式正确、量级合理、能让所有下游计算通过。**幻觉的最高形式，是让缺失看起来像完整。**

我们在这套系统里实测到七种，全部有事故对应，不是理论推想：

| 代号     | 幻觉形态              | 典型表现                                | 为什么常规检测抓不到             |
| ------ | ----------------- | ----------------------------------- | ---------------------- |
| **H1** | **填空**（尺寸链自动闭合）   | 链差 5，模型"推导"出这 5，模型完美通过              | 补出来的值格式正确、量级合理、使全部校验通过 |
| **H2** | **同源自证**（用自己证的自己） | 用自建的期望值验自建的模型                       | 闭环完美，报警率恒为 0           |
| **H3** | **无标注的置信**        | R24 读成 R19.2，语气与读对时完全相同             | 输出里没有置信度字段             |
| **H4** | **静默降级**（假装跑过）    | 工具失败 / 正则没匹配，顺势报告"通过"               | 输出与"真通过"逐字相同           |
| **H5** | **冲突合理化**（自动圆场）   | 图上画 3 个 Ø25、标注写 2×Ø25，模型挑一个讲得通的解释继续 | 结论读起来比"停"更专业           |
| **H6** | **跨件套用**（记忆污染）    | 把上一件的比例尺 / 默认倒角 / 典型结构用到这一件         | 结果落在合理范围内，无从察觉         |
| **H7** | **虚构出处**          | 编一个不存在的标注编号或剖面位置来支撑结论               | 编号格式合法                 |

**判别方法只有一个：假设我错了，它会报警吗？**

答案是"不会"的那条判据，不是在保护你，是在给你虚假的安心。

### 0.3 两个阶段各自在关掉什么

| 阶段       | 约束的幻觉             | 核心手段                     | 一句话            |
| -------- | ----------------- | ------------------------ | -------------- |
| **信息获取** | H1 H3 H5 H6 H7    | 证据绑定、数字走脚本、判不出就停         | **不给幻觉留填空的位置** |
| **校核检验** | H2 H4 + H1·H6 的残留 | 通路分离、可执行算式、watchdog、对照试验 | **不让幻觉验证幻觉**   |

这两句是全文的骨架。下面 §2、§3 的每一条规则，都是它们的具体展开。

## 2. 第一部分：信息获取阶段

> **这一阶段的全部工程设计，只做一件事：不给大模型留"填空"的位置。**
>
> 大模型在这里的本能是**补全**——看到不闭合的尺寸链就补一个数把它闭合，看到含糊的视图就给出一个自信的判定。它的补全能力正是它的价值，也正是它在这个领域的致命缺陷。所以信息获取阶段不是"让它读得更多"，而是把它的输出通道**收窄到只能写有出处的结论**。

### 2.1 这不是 OCR，也不是"看图"

外行的直觉是：读图 = 认字 + 认图形。实际读一张机械图，是**解一个欠定的约束系统**：

- 图纸给的是**约束**（尺寸、公差、符号、剖切关系），不是坐标。
- 真正要还原的是**三维实体**，而图纸只给了它的若干投影 + 若干尺寸。
- 缺失的自由度，必须由**投影律**（三视图对齐、剖面线、标准件约定）补出来。
- 补不出来的，就是"缺信息"——**缺信息不是可以猜的地方，是必须停的地方。**

所以第一阶段的产出物不是一个"识别结果"，而是一个**带证据等级的、可被质询的约束集**。后面所有闸门都建立在这个证据集上。

### 2.2 数据源有五级，能力下限由图确定

| 级   | 数据源                  | 能否建   | 说明                       |
| --- | -------------------- | ----- | ------------------------ |
| L1  | DWG → DXF（矢量 + 标注实体） | ✅ 可以  | 唯一能自动化的入口                |
| L2  | PDF（有文字层）            | ⚠️ 有损 | 文字层小数点常被画成 `:`，需吸附纠错     |
| L3  | PDF 扫描 / 图片（渲染）      | ❌ 不可  | 无矢量，尺寸链不可能闭合             |
| L4  | 人肉口述 / 拍脑袋           | ❌     | 无证据                      |
| L5  | 无源，凭经验补              | ❌     | 只能进 `predicted`，不得当闸门期望值 |

**红线：无矢量源 → `NO_BUILD_DIMTABLE`，直接退出。** 我们没有手写 DWG 二进制解析器，也不打算写——这是纯粹的无效工作，而且错一个字节就静默给出错误几何。

**这一条的代价被严重低估。** 大量现实中的图纸交付是 PDF 或扫描件。第一个门就把可处理量砍掉了一大截。

### 2.3 图层不能按名字认

同批图纸里，粗实线的图层命名至少三种体系并存：

1. 按用途：`实线` / `细实线` / `标注` / `点划线`
2. 拼音缩写：`cu`（粗）/ `xi`（细）/ `dian`（点划）
3. **全图不分层，所有实体都在图层 `0`**

一个只认 `粗|0.5|CONTINUOUS|轮廓` 的实现，在本批 7 件里 **3 件直接报 `E3: 无粗实线几何`**，整个分区断掉。图是对的，是判据太窄。

修正后的判据：

- 判据落在**线的性质**上（线宽、连续性），图层名只作提示。
- 主判据出 0 个框时，把图层 `0` / 空图层全部当粗实线重跑一次（兜底）。
- `细实线` 必须被"细"先踢掉，不能只靠"粗"来命中——顺序错了会误纳。

**教训：按名字排除比按名字纳入更危险。** 我们曾把 `轮廓线层` 写进排除表，结果它正是最常见的粗实线命名。

### 2.4 视图分区：一个坐标系只放一个视图

拿到 DXF 后，第一件事不是找尺寸，是**分区**：把整张图按区域切开，每个区域是一个视图。

先剥图框和标题栏，再求包围盒。不剥的话，"粗实线"里包含图框 + 标题栏，包围盒就是整张图——**本批曾因此把 6 个件误判成"半剖"**。

分区失败的后果是致命的：`拨叉` 的两个视图间距小于间隙阈值，`region-box` 把整张图聚成**一个 410×287 的区域**。一个坐标系里塞了两个视图，所有后续投影关系全错。依硬门禁，**分区没切开就不能进尺寸链**，直接硬停。

### 2.5 视图类型：唯一允许"判不出就停"的门

每个区域必须先把视图类型定死：外形 / 全剖 / 半剖 / 阶梯剖 / 局部剖 / 旋转剖。

这是全流程最重要的一道门，因为**视图类型决定了几何怎么读，读错了后面全错，而且闸门看不出来**：

- **半剖**：唯一判据是"另一半没有轮廓线"。剖面线只画一侧 ≠ 半剖（那可能只是画法习惯）。右置视图是左视图（看左端面），同心圆组不能绑错端。
- **阶梯剖**：剖面平面是折的。**图纸不给折线位置 → HARD_STOP，立刻问人。** 这里必须停——阶梯剖的折点位置是纯几何信息，图上没标，任何猜测都能通过投影检验，等于没检验。
- **旋转剖**：A-A 左右半径不一定相等，因为剖切线本身是折的。**绝对不能当成回转轮廓来读**——孔要按真实方位角单独放，不能转成环形槽。
- **局部剖**：先找细实线波浪线。孔只画了一段（短于标注）≠ 冲突。

**经验规则进 review.md，不进闸门。** 用经验补出来的尺寸一律标 `Inferred_Dimension`，落到复核清单的高风险条目里，不参与期望值。

### 2.6 标注 > 几何：一条不可交换的序

读图的信息有两条通道：**文字标注** 和 **几何量取**（量图纸上的线段长度、半径）。

**硬规矩：文字标注 > 几何量取。两者冲突，无条件服从标注。**

为什么？因为标注是**设计意图**，几何只是**表达方式**。图纸按某些比例绘制，几何长度 ≠ 真实尺寸。

实测事故：一个 R24 的圆弧，几何量出来是 R19.2。差 20%。如果按几何读，件直接错。真因是图按 1:1.25 画（几何 = 真实 × 0.8）。**R19.2 不是冲突，是画法。**

所以第一阶段必须先做**比例尺探针**：取若干对"标注值 / 该标注的定义点间距"，求比例 `k`。k 不接近 1 而接近某个整齐值（0.5 / 0.8 / 2 …），说明图纸是缩放绘制的，后续所有几何量都要除以 k。

**比例尺没探明之前，任何几何量取都不能作为证据。**

### 2.7 尺寸链：闭合或报缺

尺寸链的任务是：把零件所有特征的位置和大小，串成一条从基准出发、能闭合到总长/总高/总宽的链。

- **闭合 → 直接建模，不停下来问。**
- **不闭合 → 报缺哪个数，绝不自己猜一个往下画。**

这条规则的代价是直通率，收益是**每一个建出来的件都可被审计**。

实测本批 7 件里 5 件没能建成，全部由这一条触发（不是能力不足）：

| 零件  | 硬停原因                                                         |
| --- | ------------------------------------------------------------ |
| 连杆  | 只有 1 个视图，**完全没有厚度/壁厚标注**，也没有第二个视图能反推                         |
| 摇臂  | 图上实画 **3 组** Ø25/Ø10 圆，标注只写 **2×Ø25 / 2×Ø10**。是漏标还是误画？直接决定体积 |
| 拨叉  | 视图分区失败（两视图连成一块）                                              |
| 支架  | 主视图被折断线截断，右视图的 Ø28 凸台在主视图里找不到对应轮廓                            |
| 升降架 | 本轮未展开（可做，未做）                                                 |

这五个不是"工具不够聪明"，是**图纸本身缺信息或自相矛盾**。人能读出来，是因为人会**做假设并承担责任**；我们读不出来，是因为我们的验收标准要求可证明。

### 2.8 产出物：`plan.spec.json`

第一阶段结束时的产物，是一个**完整的、可执行的建模计划**：

```json
{
  "part": "件名",
  "axis_map": { "sw_x": "图纸主视 X", "sw_y": "图纸主视 Y", "sw_z": "厚度方向" },
  "bbox": [w, h, d],
  "theory": { "volume": 0, "com": [0,0,0], "bbox": [w,h,d], "source": "独立计算脚本路径" },
  "steps": [
    { "id": "B1", "op": "add_extruded_profile", "pts": [[0,0],[60,0],[60,30],[0,30]],
      "depth": 8, "dV_theory": 14400 },
    { "id": "B2", "op": "cut_sketch", "sketch": "Holes",
      "contours": [[x,y,r], "…"], "dV_theory": -2010.6 }
  ],
  "gates": { "volume": 0, "com": [0,0,0], "bbox": [w,h,d] },
  "pending_review": ["未注圆角", "…"]
}
```

关键点：**每个 step 必带 `dV_theory`**（解析值），而且 `theory` 必须注明**独立来源**。这个字段是整个第二阶段能成立的前提。

**但 `plan.spec.json` 目前仍是人工写的。** 这是自动化程度的天花板——判断"这个视图是半剖还是全剖""这个数是不是缺了""两种建法选哪个"，至今没有自动化。计划写不出来，后面就没有东西可执行。

### 2.9 信息获取阶段的成本在哪

成本不在"识别"上，在**判"停"上**。每一个硬停决策都是：

1. 穷举可能解释
2. 检查每种解释能否通过投影检验
3. 若多种解释都通过 → **不能选**，停止

第 3 步是反直觉的，也是最贵的：它把"看起来对"从一个完成信号变成了一个**报警信号**。

### 2.10 本阶段的幻觉约束对照表

| 幻觉           | 在哪一条规则里被关掉                              | 具体做法                                       |
| ------------ | --------------------------------------- | ------------------------------------------ |
| **H1 填空**    | §2.7 尺寸链闭合或报缺                           | 不闭合 → 报**缺哪个数**，不补；兜底反推值只能进 `predicted`    |
| **H3 无标注置信** | §2.2 矢量源 + §2.6 比例尺探针                   | 数字一律走脚本，禁像素反推；比例尺没探明前几何量不作证据               |
| **H5 冲突合理化** | §2.7 尺寸链 + §2.5 视图门禁                    | 同一量两个值 / 视图类型判不出 → **HARD_STOP**，不许挑一个讲得通的 |
| **H6 跨件套用**  | §2.6 + 证据 sha8 绑定                       | 每条证据绑到具体图纸哈希，换件即失效，不能带过来                   |
| **H7 虚构出处**  | §2.8 `plan.spec.json` 的 `theory.source` | 期望值必须注明独立来源文件；写不出路径 = 没有出处                 |
| 通用           | 三大宪法①                                   | 证据链完整性 > 结论流畅度；**允许输出"我不知道"**              |

**本阶段的成本几乎全部花在"判停"上，而不是"识别"上。** 识别是大模型最擅长、也最不稀缺的能力；判停才是它最不愿意做、最需要被机制强制的事。

## 3. 第二部分：校核检验阶段

> **这一阶段的全部工程设计，只做一件事：不让大模型用自己的推导去验证自己的产出。**
>
> 大模型最危险的幻觉不是"编错"，是"编对"——它把一个自己补出来的值当成既有事实，再拿它去校验一个由同一个值建出来的模型。**两边都是它写的，闭环严丝合缝，报警率为零。** 这就是 H2。
>
> 拆这个东西只有一条路：**把期望值的产生路径和模型的产生路径物理隔开**，让它们不可能同源。

### 3.1 为什么"建完量一下体积"不算校核

这是本文最重要的部分，也是最容易被误解的部分。

天真的做法：建完模型 → 用 SolidWorks 读体积 → 与自己算的理论体积比 → 差 <1% → 通过。

**这个闸门是无效的，因为它的期望值来自它自己。**

设想：你从图纸上读出某个台阶尺寸 30 mm。你按 30 建。理论体积 = f(30)。SolidWorks 建出来 = f(30)。两者必然相等——**你没有验证任何东西，你只是验证了 SolidWorks 会做乘除法**。

真值必须有**独立出处**。我们把它写成了三级证据表：

| 级   | 来源                 | 能否当闸门期望值          |
| --- | ------------------ | ----------------- |
| 1   | 图纸文字标注（尺寸、公差、符号）   | ✅                 |
| 2   | 标注推导（尺寸链闭合算出来的）    | ✅                 |
| 3   | 剖面线 / 剖面结构（有料/无料）  | ✅                 |
| 4   | 几何量取（量图上的线）        | ⚠️ 仅当比例尺已探明       |
| 5   | 标准/模板默认（"一般倒角 C1"） | ❌ 只能进 `predicted` |
| 6   | 经验兜底 / 反推补块        | ❌ **绝不当期望值**      |

**自检句：假设我错了，它会报警吗？**

如果答案是"不会"，这条判据没有校验价值，应当删掉。它不是在保护你，是在给你虚假的安心。

### 3.2 三项闸门：体积 + 质心 + 包围盒

三项全过才算成，容差 `max(0.1 mm, 1%)`——大件按比例，小件保绝对精度。

**为什么只对体积会漏东西：**

一个斜孔按直孔建，体积只差 **0.093%**。体积闸门（1% 容差）照样放行。但件是错的：孔的位置和方向都错了。

体积是标量，它**丢掉了位置信息**。质心和包围盒把位置信息补回来：

- 质心偏差 → 抓方位错（孔开在对面、凸台在错误一侧）
- 包围盒 → 抓尺寸整体错（某个方向的尺寸取错了）

实测显示：气门摇杆轴支座的质心偏差 ≤0.010 mm，摇杆 <0.001 mm。这已经给出一个非常强的方位校验。

### 3.3 三条自证失败模式

这是我们在自建系统时，**自己**踩进的三个坑。它们不是理论担忧，是实测事故。

#### 模式 A：同源自证（30 vs 35） · H2

某个特征，图纸上标 30，几何量出来 35。

- 如果你用几何量出的 35 去建，用几何公式算理论体积 → 自洽，通过。
- 如果你用标注 30 去建，用标注公式算理论体积 → 自洽，通过。
- **两条路都能通过闸门，而它们差 10.40%。**

这就是"同源自证"：期望值和被检验量来自同一条信息通路。它看起来是一个闭环，实际上是一个回音室。

泵体上的实例：错误的建法（GM）体积 245,823.3，正确的（GM5）271,399.8，差 **25,576.5 mm³ = +10.40%**。体积闸门、包围盒、质心——**全都在容差内，全部放行**。只有做了独立期望值计算才抓得住。

#### 模式 B：残数补块（35 − 30 = 5） · H1

尺寸链不闭合，差 5。于是我们让程序"自动补一个 5 的块"把链补上。

这个补块：

- 没有任何出处（图上没写 5）。
- 但它让体积算对了、包围盒算对了、质心算对了。
- **它让整个闭环变得完美且完全虚假。**

这比模式 A 更隐蔽，因为模型是彻底的臆造，但所有闸门都说是对的。

规则：兜底反推值**只准写进 `predicted` 字段**，绝不准充当闸门期望值。数学兜底只在完全无标注时启用，而且必须标注 `predicted`，并在复核清单里列出来。

#### 模式 C：视觉数值反推 · H3

让视觉模型"看图读出 R24"。

- 要么读出 R19.2（按几何像素），要么读出 R24（按标注）。
- 如果它读的是几何值，而你没做比例尺校验，你会得到一个"看起来有出处"的错误数值。

规则：**视觉只回答"有没有 / 是什么"，尺寸和坐标准一律走矢量 + 脚本，禁止像素反推。**

### 3.4 可执行算式闸（R8a）

单一的"标注 > 几何"不够强。真正能抓住同源自证的做法是：**要求每个推导出来的值，其计算过程是一条可执行表达式**，而且表达式里只能出现：

- `@参数名`（声明过的标注）
- `@E0019.lo` / `@E0019.hi`（某条证据的区间端点）
- `#E0019`（引用某条证据的值）
- 运算符
- 常数 0 / 1 / 2

**裸常数一律拒绝。**

为什么？因为裸常数 `@E0019.hi - 5` 里的那个 `5`，就是模式 B 的补块。它没有出处。拒绝它，等于强制每个数字都必须来自某条已声明的证据。

拒绝后怎么办？**把它提升为一条 tier-6 假设**，写进复核清单——"我假设这里差 5"，而不是"这里差 5"。

### 3.5 剖面拓扑闸（R8b）

**这是整个校核体系里最有效的单一闸门。**

判据一句话：**图上的剖面线说这个位置有料，你的模型里就必须有料。**

具体实现：把零件在若干剖切平面上切片，对比"图纸的剖面线填充区域"和"模型的实体区域"。连续不匹配超过 **0.5 mm** 触发。

为什么它有效？因为剖面线是**独立的第三条信息通路**：

- 它不来自尺寸标注（标注可能漏）
- 它不来自几何量取（几何可能有比例尺问题）
- 它是设计者**直接画出来的"这里是什么材料"的声明**

而且它**绕不过同源自证**：你不能用"我从尺寸推出这里应该有料"来证明"这里应该有料"，因为图已经画了，你的模型必须和它对上。它是外部真值。

实测抓到：支架的筋被漏建。**5 条虚线只取支持假设的 5/7 条**——模型通过了所有体积相关闸门，但剖面线对不上。

#### 构造这条闸门时的教训：更多切面 ≠ 更好

我们试过把 R8b 从 2 个剖切平面扩到 **26 个**。

结果：26 个平面里 **25 个报警**，最长连续不匹配 40.00 mm，错误面积 **145.82%**。

结论：**这是一台假阳性机器。**

根因：剖面线本身只画在少数几个位置。你在没有剖面线的地方切一刀，"该区域应当有料"这个前提根本不存在——你不是在检验，你是在凭空生成期望值，然后对比"没有期望值"和"有料"，必然不匹配。

**教训（写进本文的通用规则）：增加校验维度时，必须同时增加该维度上的真值。没有新真值，多出来的切面只把噪声放大。**

#### 已知盲区

R8b 有一个真实盲区：**夹在剖切平面内的补块不可见。**

一个"残数补块"（模式 B）如果恰好躺在一个剖切平面上，它从任何角度切都看不见。实测：用独立建法（GM）和修正建法（GM5）生成的模型，**R8b 的输出逐位相同**。

所以 R8b 不能单独用，必须配 X 向孤岛检测（R8b-2）。

#### R8b-2：X 向孤岛检测

专门抓"窄长条状补料"。四个条件同时满足才触发（避免误报）：

1. 单个实体在 X 向跨度 < 25 mm
2. 在 ±5 mm 的 Y 邻域内，存在一个 Y 向跨度为它的 3 倍以上的实体
3. 该状态在 Z 向持续 ≥ 20 mm
4. X 向端点漂移 < 1 mm

实测：抓到 GM（Y=30.4~34.8、Z=11.3~35.3、只出现在 X=49~59），对 GM5 **静默**（正确的建法不会触发）。

### 3.6 静默即失败（watchdog）

最危险的失败不是"判错"，是"没跑"。

一个闸门如果因为参数缺失、文件不存在、正则没匹配上而**静默跳过**，它的输出看起来和"通过"一样。你会以为自己有 9 道闸门，实际上在使用 3 道。

规则：**每条闸门必须返回一个数值或一个布尔值。静默 / 未覆盖一律判 FAIL（exit 9）。**

配套的还有**图元覆盖对账闸门**：图纸里每一条线、每一段弧，都必须被某个特征"认领"，`unclaimed > 0` 判 FAIL。虚线层单独过一遍。

这一条直接来自支架的教训：**只取支持假设的 5/7 条虚线**，模型照样过闸。全覆盖对账会让剩下 2 条虚线无处可藏。

### 3.7 恒真判据：你以为是证据，其实是恒等式

一条判据如果是恒真的，它永远不报警，你永远不知道它坏了。

**两个典型：**

1. **"N 次 0 冲突"** —— 如果分母（可冲突的机会数）是 0，这个"0 冲突"是恒真的。它不是证据，是空集上的一次计数。

2. **"剖面线全部匹配"** —— 如果剖面线只覆盖了零件 3% 的面积，那么"100% 匹配"几乎不携带信息。要看**覆盖率**，不只看匹配率。

**判别方法就是那句自检：假设我错了，它会报警吗？**

如果构造一个明显的错误，这条判据还是报警不了，就删了它——留着只是喂你虚假信心。

### 3.8 对照试验：证明闸门会放行

一个闸门只能证明它会"报警"是不够的。**它还必须证明在正确的输入下它会"不报警"。**

我们做了 7 组对照试验：

| 组      | 构造                  | 期望             | 结果           |
| ------ | ------------------- | -------------- | ------------ |
| a1     | 推导值缺 `expr`         | exit 6         | ✅            |
| a2     | 复算不一致               | exit 6         | ✅            |
| a3     | 裸常数 `@E0019.hi - 5` | exit 6         | ✅            |
| **a4** | **干净的输入**           | **exit 0**     | **✅ 放行**     |
| b1     | GM 错误建法             | exit 8         | ✅            |
| b2     | M6 深度 10→15         | 缺陷位置移动         | ✅ Z17 → Z120 |
| b3     | GM5 正确建法            | exit 8 但孤岛判据静默 | ⚠️           |

**a4 是关键。** 没有 a4，你无法区分"闸门正确报警"和"闸门永远报警"。

**b2 证明闸门在测量，不是在猜。** 改变一个尺寸，缺陷报告的位置从 Z17 精确移动到 Z120。这说明闸门读的是几何，不是某个硬编码分支。

**b3 展示了盲区是真实的**：正确的模型也可能触发 R8b（因为剖面线布局和模型不完全吻合），需要 R8b-2 来判断。这也是为什么需要多层闸门。

### 3.9 校核检验阶段的成本

这一阶段的工程成本，**比建模本身高一个量级**。

- 9 道闸门 + 1 个 watchdog + 覆盖对账，每一道都要做对照试验（正例必须放行、反例必须报警）。
- 每抓到一个假阳性，都要判断是"闸门错了"还是"模型错了"——我们的一次 26 平面实验花了相当大的精力才确认是闸门错了。
- 理论值的独立计算（栅格积分、扫描线、Green 公式、外部布尔）本身就是一个建模项目。

实测收敛表（体积栅格积分）：

| 网格 dY/dZ      | 偏差      |
| ------------- | ------- |
| 0.4 / 1.5 mm  | +1.464% |
| 0.2 / 0.75 mm | −0.055% |
| 0.1 / 0.4 mm  | −0.038% |

**第一版用了 0.4/1.5，兜底规则把它自己抓了出来。** 如果当初直接信了第一版，"理论值"本身就是错的，整个闸门体系是拿错误去验错误。

### 3.10 本阶段的幻觉约束对照表

| 幻觉             | 在哪一条规则里被关掉              | 具体做法                                 |
| -------------- | ----------------------- | ------------------------------------ |
| **H2 同源自证**    | §3.1 证据分级 + §3.4 可执行算式闸 | 期望值通路与模型通路物理分离；tier 6 永不充期望值；裸常数拒绝   |
| **H4 静默降级**    | §3.6 watchdog + 图元覆盖对账  | 每条闸门必须返回数值或布尔；静默 / 未覆盖判 FAIL（exit 9） |

## 4. 为什么没有商业价值：管道方向反了

前面所有内容都是"我们做到了"。下面是"为什么它卖不掉"。

这里有两层原因，**层次不能搞反**：

- **第一层是结构性的**——管道方向反了，需求本来就不在这儿。这是根本原因。
- **第二层才是成本**——就算缝隙里有单，也算不过账。

### 4.1 管道方向：3D 是主产品，2D 是派生物

现代机械设计的实际链路：

```
概念 → 三维模型（主产品）→ 二维工程图（派生物）→ 加工
         │                      │
         ├─ CAE / CAM           └─ 标注、公差、工艺、检验要求
         ├─ 装配 / 干涉检查
         └─ BOM / 采购
```

- **三维模型承载设计意图**，是下游一切（强度、加工、装配、BOM）的源头。
- **二维工程图是投影 + 标注的产物**，是给制造部门的交付格式。
- 出图是**单向**的：模型改了，图重出；图改了，模型必须跟着改——否则模型就是旧的真值。

所以"从 2D 造 3D"不是生产流程的一环，是**修复缺失数据**的补救动作。它就是逆向工程。

**这条管道的方向直接决定了市场形状：凡是还在设计、还在生产的零件，三维模型本来就有。** 客户要么已经有一个，要么可以花更少的力气现做——因为设计和装配关系还在他手里。

再看我们的实测：11 件批直通率 73%，7 件批 29%。后者掉下来的原因全部是图纸缺信息或自相矛盾。

**而图纸质量差的，恰恰就是三维模型已经丢失的那一批。** 这不是巧合，是同一个成因：三维源头没了的零件，二维图也往往是最老的、最不规范的、多年没人维护的那一份。

于是形成一个闭环：

```
好图纸的零件  → 三维早已存在 → 不需要我们
需要我们的零件 → 三维已丢失   → 图纸最差 → 直通率最低
```

**这个相关性是结构性的，不是抽样偏差。**

### 4.2 需求只存在于四种缝隙里

| 场景              | 需求来源                          | 特征           |
| --------------- | ----------------------------- | ------------ |
| **老图数字化**       | 手工绘图时代只有 2D，或 3D 文件已丢失 / 格式不通 | 一次性、批量小、图纸最差 |
| **外来件 / 国产化替代** | 供应商只给图纸不给模型                   | 图纸不归你控制      |
| **有图无模型的合规建档**  | 档案里有图，要算强度 / 工艺 / 装配干涉        | 不打算重新设计      |
| **教学 / 建库**     | 建标准件库或示例库                     | 预算接近零        |

四个场景的共同点：

- **一次性**：一家厂一年可能就几十张老图要转，不是天天做。
- **低批量**：没有规模效应可摊。
- **输入最差**：老图、手绘、扫描件、旧标准、图层混乱。
- **目的不是产生新价值，是补旧账**：定价逻辑是"整理档案"，不是"创造产能"。

（实物测绘 → 3D 是另一码事，走三维扫描 + 逆向曲面，不属于本文的 2D→3D 范畴。但它同样印证了管道方向：**3D 一旦存在，没有人从 2D 反推。**）

### 4.3 缝隙的客户画像，和我们能卖的东西正好相反

| 客户要的    | 我们能给的                    | 冲突         |
| ------- | ------------------------ | ---------- |
| 便宜      | 每件都要独立读图 / 闭链 / 算理论值     | 固定成本摊不薄    |
| 快       | 硬停就要停下来问人                | 速度被证据链卡住   |
| "差不多能用" | 三项闸门全过，或者不做              | 全有或全无      |
| 一张能看的图  | 我们最强的是**证明它对**           | 最贵的部分客户不付钱 |
| 不验收     | 验收方是档案 / 工艺部门，自己也不知道正确答案 | **没人能验收**  |

最后一行最致命：

**逆向工程的客户，恰恰是最没有能力、也最没有动力去验收"证明"的客户。**

他们买的不是"正确"，是"看起来对、能交付、出了事别找我"。我们能交付的是"三项闸门 3/3、R8b 剖面拓扑无冲突、复算闸通过"——这些对一个要把老图转进 PLM 系统的人来说，**既看不懂，也用不上，更不肯为它加钱**。

这不是定价问题，是供需错配。降价解决不了：降到最后，我们就是在卖一个比人工慢、还不一定能交付的东西。

### 4.4 成本结构：乘法，不是加法

自动化的经济性来自"边际成本趋零"。这个前提在这里**不成立**。

原因：**每张图纸都是一个独立问题。**

- 同一个零件的两个视图，你不会建两次。
- 但两张图纸的特征组合，几乎不重样。
- 固定的只有**判据和闸门**，变化的是**每一个数字**。

所以这里的固定成本（写流水线、做闸门、写理论计算）被摊到**每一件**上，而每件依然要**单独读图、单独闭链、单独算理论值**。

我们用同一套模板做了 11 件，单件仍然要 0.17~0.45 h。这是"已经知道怎么建"之后的**执行**时间，**不含**读图和写 `plan.spec.json`（后者目前仍是人工）。

### 4.5 期望工时的公式

设：

- `T_man` = 纯人工建模一件的工时（含读图），典型 2~4 h
- `T_auto` = 自动流水线执行一件的工时（不含读图），0.2~0.5 h
- `T_read` = 自动流水线仍需人工读图 / 写计划的工时，**目前 ≈ 纯人工的 40%~60%**
- `p` = 直通率

**关键：硬停不是"便宜一半"，是"还要人从头再来一遍"。**

一件硬停的零件，成本 = `T_auto + T_read + T_man`（自动跑一遍 + 人工读图 + 人工重建），**比纯人工更贵**。

期望节省：

```
E[省] = p · (T_man − T_auto − T_read) − (1 − p) · (T_auto + T_read)
```

代入 `T_man=3h`, `T_auto=0.35h`, `T_read=1.5h`：

| 直通率 p        | 期望节省      | 结论        |
| ------------ | --------- | --------- |
| 100%         | +1.15 h/件 | 省 38%     |
| 73%（11 件批实测） | +0.34 h/件 | 省 11%     |
| 62%          | ≈ 0       | **打平点**   |
| 29%（7 件批实测）  | −0.98 h/件 | **亏 33%** |

**盈亏平衡点：直通率 61.7%。掉到这条线以下，这套系统比纯人工贵。**

而实测的直通率是 73%（好的批次）和 29%（真实的批次）。

### 4.6 分母问题：73% 是个乐观值

我们的直通率是在**自选样本**上测的。真实客户交付的图纸，包含：

- PDF 扫描件（无矢量，不可建）
- 未分层 / 命名混乱的 DXF（需人工修图）
- 缺视图 / 缺厚度的图纸（尺寸链不闭合）
- 图纸内部矛盾（同一尺寸两个值、标注与实画不符）
- 装配图（BOM 多名、无剖面线、螺栓双套线 → 只能建代表件）
- 老图 / 归档图（GBK 编码、旧标准）

**我们没有理由相信客户图纸的自洽率高于我们自选的样本。相反，客户越着急找你自动化，图纸越可能是一堆没人愿意干的活。**

这就是长尾：能处理的图纸集中在"自洽且完整投影"的头部，而这部分图纸恰好也是**人工建最便宜**的部分。

**经济效益最好的部分，恰好是最不需要自动化的人类已经干得最快的部分。**

### 4.7 责任不对称

- 人工建的零件错了 → 责任在工程师，客户按合同找工程师。
- 自动建的零件错了 → 责任在工具，客户按合同找供应商。

所以自动化的错误率必须**远低于**人工才敢卖。而把错误率压低的唯一手段，是提高硬停率。

**这构成一个不可能三角：**

```
        低错误率
         /     \
        /       \
   低成本 ——— 高直通率
```

三者最多选两个。压低错误率 → 硬停率上升 → 直通率下降 → 期望工时上升 → 成本上升。

人工不面对这个三角，因为**人可以做假设并承担责任**。这不是"人的能力比 AI 强"，是**商业责任的分配方式**不允许我们把假设当作结果。

### 4.8 但校核检验阶段是顺着管道的

把第 2 部分独立出来，结论完全不同——因为它**不需要逆着管道走**。

正向流程里本来就有一个环节：**三维建出来之后，核对它和二维图是否一致。** 这不是我们发明的新需求，是设计院、工艺科、模具厂每天都在做的事。区别只是他们现在靠人眼、靠抽查、靠老师傅。

它满足一个产品该有的全部条件：

- **顺管道**：3D 已有（自家设计的），2D 已有，只差对账。
- **刚性**：模型错了，后面 CAM、模具、装配全部连锁报废，所以钱必须花。
- **高频**：每个新零件都要过一遍，不是一次性补旧账。
- **不承诺建出东西**：所以不承担硬停风险。审不出来就说"审不出来"，本身就交付了价值。
- **价值可量化**：拦下一次 10.40% 的体积错误 = 避免一次模具返工。

我们的校核体系，哪怕完全不做自动建模，也能直接用在**人建出来的模型**上：

- 三项闸门（体积 / 质心 / 包围盒）
- R8a 可执行算式闸（抓自证补块）
- R8b 剖面拓扑闸（抓漏特征）
- 图元覆盖对账（抓"只取了支持假设的那几条线"）
- watchdog（抓"静默跳过"）

**它能审人建的模型，不需要先建。**

而这些闸门恰恰是整套系统里最贵、最难做对的部分——成本我们已经付过了。

一句话概括本节：

> **建模是逆着管道的补救，校核是顺着管道的工序。前者没有市场，后者有。**

## 5. 什么值得开源，什么不值得

### 值得公开

1. **幻觉约束总表**（附录 C + §0.2 的 H1~H7）。这是唯一完全不依赖具体图纸、也不依赖具体 CAD 的资产。任何"LLM 参与工程数据"的场景都能直接搬。
2. **两条元规则**（§0.3）：不给填空的位置、不让幻觉验证幻觉。其余所有规则都是这两条的实例化。
3. **校核判据清单**（附录 A）与三条自证失败模式（§3.3）。做"从图纸 / 图片反推几何"的人一定会踩。
4. **对照试验方法论**（§3.8）：正例必须放行、反例必须报警、缺陷位置必须随参数移动。没有 a4 的闸门测试等于没测。
5. **收敛表与假阳性教训**（§3.5、§3.9）。用时间和错误换来的，公开它们能省掉别人的一次 26 平面实验。
6. **实测战绩**（§1.1）与**直通率**（§1.2）。完整地说"做到了什么"和"没做到什么"。

### 不值得公开 / 不值得继续做

1. **建模流水线本身。** 它是为一类图纸调的配方，换一批图纸就要重调；更根本的是**它逆着管道走**（§4.1），需求端就没有它。经济性我们也算过不成立。
2. **自动补块 / 兜底反推。** 应该彻底删除，而不是保留配置开关。它们的唯一效果是把一块空地伪装成实心。
3. **"识别更多特征"的路线。** 每解决一类失败，就会出现一类新的。分支数随失败数增长，是一个已经失控的信号（我们在自建系统时就撞上了这一点，见"退役机制"）。
4. **把 63 张练习图或 JPG 批量建模。** 已被证明不成立：尺寸链缺"点对"信息，识别出的特征标签会瞎编。

## 6. 复现

如果你想验证本文的结论，最小路径是：

```
1. 取一张真实机械图（最好是 PDF 扫描，最贴近现实）
2. 尝试把它的尺寸链写成一个可执行的 plan.spec.json
3. 停在"缺哪个数 / 哪个视图是什么剖"上，记录被迫停下的次数
4. 如果 ≤2 次，再尝试建；>2 次，本文的结论已经在你自己这里被复现了
```

完整流程的八个阶段：

`S0 分区 → S1 读标注 → S1.5 视图门禁 → S2 尺寸链 → S2.5 多视图交叉 → S3 理论体积 → S4/S5 离线预检 → S6 一次跑完 → S7 收尾`

S4/S5 的四条不变量（调 CAD 之前必须全过）：

1. `|n| = 1`（法向单位化）
2. `n · x = 0`（法向与轴向正交）
3. `cos(法向, 孔轴) = ±1`
4. 回读坐标与计划一致

任何一条不过 → 回改计划，**不要在 CAD 里试**。在三维软件里试错，一次失败就污染了整个上下文，是成本最高的调试方式。

## 结语

我们证明了三件事。

**一、关于方向：**

> 零件是**先有三维，后有二维**的。二维图是三维模型的产物，不是它的来源。
> 从二维反推三维，是在一条已经流下去的河里往上游捞东西——能捞到，但只有那些掉进河里的才值得捞。

**二、关于代价：**

> **"能被证明是对的"，比"看起来是对的"，难得多。**

前者要付出一个数量级的工程代价，后者只要能跑就行。商业上，客户买的是后者；工程上，你只能交付前者。

**三、关于幻觉：**

> 大模型在工程数据上的幻觉，不是"说错话"，是**把空缺填成一个正确答案的形状**。
> 你在输出里看不见它。你只能在两件事上把它挤出去：**它没有地方可填**，和**它没有东西可验**。

三条合起来就是这门生意的全部裂缝：

- 顺着管道的那一段（校核、评审），有人付钱，但我们把最贵的成本花在了建模上。
- 逆着管道的那一段（建模），我们做得最好，但那一段本来就没有需求。
- 而两个阶段里真正沉淀下来的，既不是建模，也不是生意经——**是一套把 LLM 的幻觉挡在工程结论之外的机制。**

**真正该卖的东西，一开始就不在我们以为的那一头。真正该开源的东西，也不是那一段代码。*

*大模型先天是概率模型 但工程不允许存在概率 尊重工程 每一个错误的可能 背后意味着财产损失 甚至人员伤亡
